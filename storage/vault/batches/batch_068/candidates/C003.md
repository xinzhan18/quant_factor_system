## 表达式解读

`Sub($eps_ttm, $operating_cash_flow_per_share_ttm)` — TTM EPS 减 TTM 每股经营性现金流。

**机制 (原假设)**: Sloan (1996) 应计盈余异象。`eps - ocf = accruals` 反映盈余质量低 (cash-light earnings) → 期待反向 IC (accruals 高 → 未来 return 低)。已发表论文在美股有效, 中国市场部分文献支持。

## CP01 Hard Gates ✗

`compute_error: ValueError: preprocessed factor is empty (all NaN)` — Phase 2 在 MAD+zscore 预处理后整个 long-form factor 为空。

**根因诊断**:
1. `$eps_ttm` 在 ref_financials 中, TTM 字段更新频率为季度 (报表期), 非交易日全部 NaN (虽有 ffill 机制但跨 universe 部分股票无 TTM 历史)
2. `$operating_cash_flow_per_share_ttm` 同样 sparse, 且 ocf 类字段在 ref_financials 同步覆盖率低于 eps (现金流量表披露口径差异)
3. DSL `Sub(a, b)` 在 a or b 任一 NaN 时返回 NaN, 不像 `Div` 有 0 处理
4. 两个 sparse 字段 Sub → NaN 比例放大 (假设各自 30% NaN, Sub 后约 50%+ NaN)
5. MAD+zscore 预处理后 cross-section minimum sample 不达 → 全 trim 为 NaN

## 反思

**升格 lessons 候选 (本 candidate 直接贡献)**: 
"TTM × TTM 直接 Sub/Mul/Div 在 ref_financials sparse 字段需 Python 包装"
- 应升格至 lessons.md `Path Selection` 段
- 规避 b068 C003 retread; 同样适用其他 (PE × ROE), (PB × growth), (eps × ocf) 等 TTM-pair operations

**机制本身仍有效** — Sloan accruals 在中国市场仍有学术证据支持。但**实现路径不可行 DSL**, 必走 Python:
1. **Approach A**: Python compute, 先 cross-section ffill (per stock × time) 两 TTM 字段, 再做 Sub
2. **Approach B**: Python compute `(eps - ocf) / |eps + ocf|` 标准化形式 (绕开 magnitude 异质性 + 减少 NaN 放大)
3. **Approach C**: cross-section z-score 后再 Sub (规避 Sub 的 magnitude 异质问题)

**复活路径**: 不复活 DSL 直接版本; 改 Python (Phase 1 spec source_type=python, REQUIRED_FIELDS=[$eps_ttm, $operating_cash_flow_per_share_ttm], 模块自带 ffill + zscore)。
