# calibration/009 · alpha_survival > 1.0 单边判定不构成 admit 充分条件 — 三连悖论触发 CP03 双门槛守护

## 证据

### Trigger 来源

connect 三连悖论 (b086 / b087 / b088 三 batch 跨 4 direction 复现):

| Batch | Cand | direction | alpha_surv | incr_ic | max_corr | verdict |
|-------|------|-----------|-----------|---------|----------|---------|
| b086 | C001 | alpha191_universal_subset | **1.59** | -0.016 | 0.46@F006 | reject |
| b086 | C005 | alpha191_universal_subset | **1.585** | -0.023 | 0.36@cluster | reject |
| b086 | C006 | alpha191_universal_subset | **1.21** | -0.007 | 0.44@F008 | reserve (borderline) |
| b088 | C001 | signed_money_flow_oscillator | **1.35** | -0.007 | 0.63@F026 | reject |
| b088 | C005 | signed_money_flow_oscillator | **1.57** | -0.005 | 0.61@F008 | reject |

历史上 alpha_surv > 1.0 罕见 (仅 b081 C006=0.99 ≈ 1.0 + b082 C002=1.20 + b082 C006=1.13 admit + b085 C001=1.13 admit + b085 C005=1.39 reserve 共 ≤5 例 in 80+ batches), b086/b088 单批 3 例 + 单批 2 例集中爆发 — **形式独立频率显著上升, 但库空间增值频率未上升**.

### 机理诊断

`alpha_survival_ratio = residualized_ic / raw_ic` 中:
- **residualized_ic** = LHS atom 对 7 个 Barra style basis (size, value, momentum, vol_20d, growth, leverage, liquidity) 做 OLS residualize 后再算 IC
- **raw_ic** = LHS atom 直接 IC

> 1.0 表示残差 IC 比原 IC 还强 — 通常解释为"alpha 主要藏在 Barra-orthogonal 子空间", Barra 噪声反而 dilute 信号.

**但是** — 库内 admitted 因子 ≠ Barra basis. F008 `upper_shadow_persistence_3d` / F026 `daily_close_position_tsrank_60` / F022 `range_compression_60` 等是 close-position-only 几何 + range-CV 几何, 不在 size/value/growth/leverage/liquidity 任何标准 Barra style 内 (Barra vol_20d 是 daily return 的 20d std, 不等同 close-position rank). 因此候选 alpha 与 Barra basis 残差可以远 > 0, 但与库内 close-position cluster cross-section rank 可以高度同构 (max_corr 0.61-0.63), 加入库后 incremental_ic 负.

### 现行 6 CP rubric 是否已覆盖

CP03 rubric 同时打 max_corr + incr_ic 两档, 6 个候选都被 reject — **现行 rubric 工作正常**. 但 b086/b088 跨候选反思反复出现"形式独立 ≠ library 充分条件"提议升格, 表示 LLM 判官在面对 alpha_surv 顶级时容易**过度 weight CP04 (alpha 残差)**, 需要明文 cross-check 守护.

### 现行 thresholds 检查

`storage/config.yaml.thresholds` 中已有 `cp03.alpha_survival_min` (per-direction 0.25-1.00) — 是 floor 保护 (防 alpha_surv 太低 reject), **没有 ceiling 守护** (alpha_surv 顶级时是否仍要双 gate). 本 finding 提议加 ceiling 守护规则.

## 实现建议

### config.yaml.thresholds 新加 cp03.alpha_survival_paradox_guard

```yaml
thresholds:
  cp03:
    alpha_survival_paradox_guard:
      enforce: true
      trigger: alpha_survival_ratio >= 1.0
      required_gates:
        incremental_ic_min: 0.005      # 必须 ≥ +0.005 (POS)
        max_lib_corr_max: 0.40          # 必须 < 0.40
      action_if_fail: |
        rubric 档位强制从 "strong/excellent" 降到 "borderline-strong";
        判官在 cross-candidate review 必须明文 cite "alpha_survival 单边
        独立但库空间 capture by F<id>" 才能 reject.
```

**注**: 这不是 hard_block (不阻断流程), 是 **CP03 rubric guidance 升级** + LLM 提示 nudge — 让"alpha_surv > 1.0 不是 admit 通行证" 这条律在判官 prompt 里显式化.
