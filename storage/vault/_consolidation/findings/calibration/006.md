# calibration/006 · CP02 alpha_survival ≥ 0.40 必须配 ic_by_year sign-stability

## 评估目标

P010 finding (pattern_analyst/011): alpha_survival ≥ 0.40 与 OOS
sign-stability 解耦. 当前 CP02 hard_gate 的 alpha_survival check 单
要件是否需要校准?

## 证据 (b071)

6/6 候选 alpha_survival ∈ [0.93, 7.23] 全 PASS 0.40 阈值, 但 6/6 OOS
sign_flip:
- C001 ROE: alpha_surv=0.93, train +0.014 / val -0.009 → sign_flip
- C002 ROIC 3-basis: alpha_surv=2.40, train +0.011 / val -0.003 → sign_flip
- C003 gross_margin: alpha_surv=1.20, train +0.001 / val -0.003 → sign_flip
- C004 ROA 3-basis: alpha_surv=1.49, train +0.010 / val -0.005 → sign_flip
- C005 growth: alpha_surv=1.95, train +0.009 / val -0.003 → sign_flip
- C006 inverse D/A: alpha_surv=**7.23** (整批最高), train +0.007 / val
  -0.001 → sign_flip

**alpha_surv 越高 (7.23 vs 0.93) 不预测 OOS sign 越稳**. 当前如果只看
alpha_surv 单要件, 这 6 候选都会被 PASS CP02, 只在 sign_flip hard_gate
处被拦截.

## 校准提案

**不调 alpha_survival 阈值数字**. 但建议:

1. **判据 composition 显化**: lessons.md `Path Selection` 段加入子条目
   "alpha_survival ≥ 0.40 必须配 ic_by_year 后期同号 check"
2. **CP02 logic 显化**: 在 judge.md template 中, alpha_surv check 块
   后追加 "ic_by_year 2022/2023 同号 check" — 当前虽然 sign_flip
   hard_gate 实际拦截, 但显化判据可减少未来类似 b071 retread 的预算浪费
3. **Pre-design 阶段建议**: phase1 idea generation 时, 任何依赖 Python
   residualize 的方向必须配 ic_by_year 验证 path, 不能仅依赖 alpha_surv

## retro 影响

retro 检查发现: 当前 sign_flip hard_gate 已经实际拦截了 b071 6/6 候选
(CP02 alpha_surv PASS 但 hard_gate sign_flip fail). **判据组合上系统正确
工作**, 只是判据语义在 lessons + judge template 上未显化, 导致 LLM 设计
新方向时可能错误依赖 alpha_surv 单要件。

## 决议

阈值数字不变, 校准是**显化已有判据 composition 到 lessons.md + judge
template**. 这是文档级校准, 不是阈值级校准。
