# calibration/003 · `coverage` 硬闸 direction-aware: barra_residual_alpha 放宽到 0.70

## 证据

batch_054 6 个候选**全部 hard_gate fail**, 其中 **5 个 coverage 在 0.708-0.725 区间**（C001 是 compute_error 不计）：

| Cand | Coverage | 其它 fail | Real signal? |
|------|----------|-----------|--------------|
| C002 | 0.709 | mono_sign_flip(-0.80→+0.70) | regime sensitive — fail 合理 |
| C003 | 0.708 | sign_flip + oos_decay=-0.644 | regime sensitive — fail 合理 |
| C004 | 0.717 | ic_oos=0.006 | noise — fail 合理 |
| **C005** | **0.725** | **单 coverage 闸 fail** | **ICIR_oos=-0.169 + alpha_surv=1.57 + style_r²=0.024 + max_corr=0.441@F008 cluster-clean** — **若 coverage 放宽则 PASS** |
| C006 | 0.717 | ic_oos=0.0003 | noise — fail 合理 |

**机制**（b054 judge 已诊断）：
- cross-sectional Barra residual ≈ 1% NaN（style 缺失传播）
- rolling 算子 min_periods≥10 要求每只标的连续历史
- csi1000 上市日异质性（早期日期 ~30% 标的尚未上市）
- 三者复合 → 全期均值 coverage = 0.71 << 0.80

**这是数据契约层结构性下界，不是因子设计问题**。barra_residual_alpha 方向 7 轮共 1 admit (F004) 部分原因是该数据契约 wall。direction-aware coverage 放宽到 0.70 让 residual paradigm 在 CP02-06 完整裁决下证明/证伪自己——而非全部死在数据契约层。

## 实现建议

```yaml
thresholds:
  hard_gates:
    min_coverage: 0.80                          # default
    min_coverage_by_direction:                  # NEW direction-aware override
      barra_residual_alpha: 0.70
```

实现：CP01 hard_gates check 时若 manifest.direction == "barra_residual_alpha" 用 0.70，否则 0.80。

## 风险与限制

- **不全局放宽**: 只在 barra_residual_alpha 这一个数据契约结构性受限的方向放宽。其它方向 coverage<0.80 仍然是真问题（数据缺失/算子定义错），保持 0.80 严格。
- **配合 T003 修复**: 若 loader 修复 (允许 residual + rolling 不传播 NaN), 这个 direction-aware 阈值可回收到 0.80。是临时 workaround。
- **alpha_surv_min.barra_residual_alpha=1.00 不变**: residual IS the alpha 的纪律不动摇——单 coverage 数据契约层放宽。
