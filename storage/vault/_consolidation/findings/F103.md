# F103 · alpha_surv-borderline reserve 系统性积压（Kurt60 / signed_illiquidity / gap_acceptance / body_pos_higher_moment）— 同一"Barra 吞噬 + library-clean"结构未被 Python residualization 救起

## Observation

近 10 batches 出现 **一个重复出现的 reserve 模式**：

| batch | cand | reserve 理由核心 |
|---|---|---|
| b045 | C001 Kurt60 | mono=0.90 + cum_mdd=-1.42 + incr_ic=+0.015 + max_corr=0.105 库空间独立；**alpha_surv=0.17 Barra 重度吞噬** |
| b046 | C006 signed_illiq | 9 年全负 + sign_c=1.0 + max_corr=0.16 库空间独立；**alpha_surv=0.17 severe poor + incr_ic=-0.031** |
| b051 | C001 gap_acceptance (`Mean(gap/(H-L),20)`) | mono=1.0 双侧 + 9 年同号 + decay=2.09；**alpha_surv=0.31 borderline + max_corr=0.55 rank-diff cluster + incr_ic=0.008 边际** |
| b053 | C001 body_pos_higher_moment | mono=1.0 双侧 + 9 年同号 + ls_Sharpe=2.45；**alpha_surv=0.37 borderline + max_corr=-0.694@F020 anti-cluster + incr_ic=0.0096 边际** |
| b050 | C001 body_ratio_5d Mean | mono=1.0 双侧 + 9 年同号；**alpha_surv=0.33 borderline + max_corr=0.50@F017** |

**共同 signature**：真实 rank-order（mono ≥ 0.9 + 9 年同号 + 强 ls_Sharpe）+ alpha_surv < 0.40（Barra style basis 吞噬大部分 PnL）+ library-proximity borderline（要么 max_corr<0.30 真独立, 要么 0.30-0.70 cluster）。

Library 20 个 admit 因子里，**没有任何一个是 Python-Barra-residual-based 的"rank-surviving alpha"**（F004/F005 是 Barra residual return 本身，不是 rank-surviving 信号的 residualized 版本）。

这意味着：库结构性缺失 "**真信号 × Barra residualize**" 这条 paradigm 的产品。

## Reserve 积压律

从 batch_045 到 batch_053 共 5 个独立 reserve 共享此 signature——**不是偶然**，是一个系统性检测不到但真实存在的 signal subspace。

现有 alpha_surv 硬门槛 (default 0.40 / acceptable 0.30) 把这类信号全部阻挡，但该阈值本身是 CP04 "Barra kill" 检测的保守设定——意图是防止 admit factor 是"伪 Barra style reshape"。对于 rank-mono=1.0 + library-independent 的真 rank-order 信号，Barra 吞噬是**信号真实暴露于已知 style factor**，而非"伪信号"——此时应该 Python residualize 后 admit residual 版本，而不是全盘 reject。

## 建议探索

1. **Python residualize 上述 5 个 reserve 候选，生成 `{original}_barra_neut` 版本**——`factor = factor - OLS(factor, Barra_styles, weights=cap)`，重测 IC / mono / ls_t。若 Barra-neutralized 版本保留 mono ≥ 0.7 + IC ≥ 0.01，该版本是"真 residual alpha"，应进入 admit 流程。

2. **若 Python residualize 路径 productive**，建议开设新 direction `barra_neutralized_alpha_library`（区别于现有 `barra_residual_alpha`——后者是从 Barra residual return 出发找信号；本新方向是从现有 signal 出发做 Barra residualize）。

3. **batch_054 coverage hard_gate 问题先修**——否则 residualize 产品全部触 coverage<0.80 fail（b054 findings）。若 Python Barra residual rolling 系统性 coverage=0.71，需要 factor-level residualize（不是 residual-then-rolling，而是 rolling-then-residualize）。

4. **给 generator 加 "reserve-regeneration" 模式**：对每个 reserve 候选自动尝试 `Barra_neut / turnover_neut / vol20d_neut` 三种 residualize 变体，省人工派生。

## severity 判据

**medium**：(1) 5 个独立 reserve 共享 signature 是强模式证据；(2) 但 Python residualize 能否破解 alpha_surv 门槛是经验性问题，没有 b054 之前的成功先例（b054 residual+rolling 刚被 coverage hard_gate 证伪）；(3) 不能独立升格为"结构性 high severity"缺口——需 b054 T003 loader fix + residual rolling coverage 解决后才能测试；(4) 但 Reserve 积压信号足够强烈，应作为 Phase 5 consolidation 的明确 "deferred evaluation queue" 记录，以免 reserve 被长期遗忘。
