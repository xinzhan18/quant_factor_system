# library_gap/004 · 条件算子 (IfElse / Mask / Gt / Lt) 在 admitted 全库零兑现

## Observation

库内 23 admit 算子使用情况：

- 数值/比较：`Sub`, `Add`, `Mul`, `Div`, `Abs`, `Log`, `Sign` 高频
- 排序/参考：`CsRank`, `Ref`, `Delta`
- 时序聚合：`Mean`, `Std`
- **条件分支算子：`IfElse` / `If` / `Where` / `Mask` 0 admit**
- **比较算子作为信号门：`Gt` / `Lt` / `Eq` 0 admit**（仅 `Sign` 在 F009/F018/F013 内部用于离散化 ±1）

**0 个 admit 包含状态依赖的条件结构**，比如：
- "if today is high-volume day, take overnight gap; else take intraday"
- "Mean(X, 20) when Std(X, 20) < threshold"（regime-conditional aggregation）
- 只在 `$close > Ref($close, 60)` (60-day uptrend) 时计算的因子

**最接近条件信号的 admit 是 F003 / F009 / F010 / F011 用 `Sign(Sub($open, Ref($close, 1)))`** —— 但这只是用 Sign 离散化方向，不是 IfElse 条件分支。

## 结构性缺口

- **regime-conditional 算子族整片空缺**：所有 admit 都是 unconditional 的 cross-section algebra。
- batch_054 揭示 "higher-moment LHS 跨 train/validation regime 翻号" 是跨 3 family 的硬律 —— 这恰恰说明 **regime-conditional design 可能是处理 regime-sensitivity 的天然解药**：用 `IfElse(Mean($amount,60) > Mean($amount,250), strategy_A, strategy_B)` 把 high-liquidity vs low-liquidity 拆分为不同 regime 内的独立信号，可能避免 b052/b054 揭示的"跨 regime 翻号"陷阱。
- batch_058 揭示 "窗口翻倍让 vol_20d 吸收翻倍" —— 这恰恰也是 conditional 的入口：`IfElse(vol_20d > median, short_window_signal, long_window_signal)`。

## 建议

不建议立即开新 direction（条件算子在 csi1000 cross-section 上是否能稳定出 alpha 是个 open question），但建议：
1. 在现有 productive direction (overnight_intraday_split / range_structure) 内**插入 1-2 个 IfElse 候选**作 paradigm 探针
2. 优先尝试 `IfElse(rolling_vol_quintile, signal_A, signal_B)` 形态——把 regime 拆出来，用 regime-stable signal 在 regime 内运作
3. 验证 DSL 层 `IfElse` 算子是否已注册（如未注册需先补）

severity = **medium**：算子族整片空缺 + 失败模式 (b052/b054 cross-regime sign_flip) 间接暗示 conditional design 是未试过的解药。但缺直接的 reserve-level 证据，纯结构性观察。
