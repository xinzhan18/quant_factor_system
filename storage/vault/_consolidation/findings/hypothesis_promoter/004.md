# hypothesis_promoter/004 · 引入 `archived` 方向状态 + 批量 archive 提案

## 该升格的 narrative 元素

- `return_distribution_signals` 2026-04-25 narrative「F300 / F301 建议状态变更 `dead → archived`，但本系统暂不引入 archived 态，维持 dead + priority=low」——**本方向已显式呼叫该规则**
- `stochastic_position` 2026-04-25 narrative「建议 status: saturated → archived（F306 promoter 建议）；当前保持 saturated 直到工具链显式 dead」
- `trend_quality_gated` Hypothesis 段「**F302** Paper transfer default 律：...建议本方向 `dead → archived`」
- 多 dead 方向的「Operations」段都标 "元教训进 lessons.md（下次 consolidation）" 后已无 active focus

## 与现有 lessons 的差异

当前 lessons.md / state model **完全没有 archived 状态**。Direction lifecycle 文档化的状态包括 `exploring / productive / saturated / dead`（本 packet 中均出现），dead 是终态但**继续被枚举**。这导致：(1) Phase 1 direction-selection 每轮都要扫一遍 10+ 个 dead 方向的 hypothesis 段；(2) INDEX.md 活跃方向列表被淹；(3) snapshot 越累越长。引入 archived 是**架构级清理**，比单纯的"降 priority"更彻底。

## 建议 lessons.md 位置

新建 `## Direction Lifecycle` 段（与 finding 001 / 003 一并），明确 5 状态机：`exploring → productive ↔ saturated → dead → archived`，archived 触发条件如本 finding 所述。

## severity 判据

`medium`：方向 archive 是**系统级元规则**，但具体的 archive 列表是**经验性提案**——可能存在该 dead 方向元教训未来被推翻的极端情况（如 F002 anchor 退役后部分 saturated 方向需 reopen，这种情况下 archived → exploring 复活路径必须保留）。规则升格立即可省 LLM context；但 archive 提案本身需要 orchestrator 人工审定。
