# pattern_analyst/008 · DSL Sub 不容错 + ref_financials TTM sparse 复合 → DSL 直接 TTM cross-product 不可行

## Pattern

ref_financials TTM 字段在 csi1000 上有结构性 sparsity（report 期外 NaN），DSL 算术算子 `Sub` / `Mul` / `Div` **不容错**——任一操作数 NaN 即结果 NaN。两 TTM 字段直接 cross-product 形式（典型如 Sloan accruals = `eps_ttm - ocf_per_share_ttm`、Magic-formula = `roic / ev`、growth-quality blend）在 DSL 层 **complete-NaN 因子**，preprocessed empty，hard_gate 数据契约失败，连 6CP 评估都到不了。

这是与"vol_20d 吸收"完全不同的失败 family——这是**数据契约层**失败，而非信号层。当前 generator 层未在 freeze 阶段 static validate 这一点；b068 C003 是首次实证。

## 证据链

- [[batches/batch_068/candidates/C003|b068 C003]] `Sub($eps_ttm, $operating_cash_flow_per_share_ttm)` → preprocessed factor empty (all NaN) hard_gate fail
- 平行案例：[[batches/batch_022/judge|batch_022]] fundamental_momentum rate-form 候选虽未 NaN-fail，但全 ic 不达 floor — 提示 fundamental DSL semantics 在 csi1000 整体 fragile

**字段 sparsity 实测**（来自 ref_financials 同步日志，2026-05-01 11 年同步~5500 股）：TTM per-share 字段 (`$eps_ttm` / `$ocf_per_share_ttm` / `$book_value_per_share_ttm`) report 期外 NaN 比例 ~10-30%，跨字段 NaN intersection 在 csi1000 daily 上 ~40%+ → Sub 后 union NaN 直接清空 cross-section。

## 建议的 direction 操作

- **fundamental_quality_carry**：narrative 已记录 T003 数据契约失败 + 复活路径必走 Python，本 finding 加固
- **lessons.md `Path Selection` 段升格**：见 frontmatter `suggested_lesson_text`，明确 generator AST 层硬阻断 + Python 因子改写路径
- **Generator 实现建议**（属 codebase 修改而非 lesson）：Phase 1 freeze static validate 加规则——`expr.top_op ∈ {Sub, Mul, Div}` 且两端 atom set 都 ⊆ {ref_financials TTM 字段} 时直接拒绝 DSL，要求改 Python 因子或换 numerator/denominator 结构（让至少一端是 daily 字段或单 TTM 字段 + scalar 常数）
