# pattern_analyst/020 · Qlib Corr cross-field start_index 不齐 broadcast crash

## Pattern

Qlib 二进制格式 `[start_index:f32][data:f32×N]` 中, **PIT valuation /
TTM ratio / `$turnover_rate`** 与核心 OHLCV ($close/$open/$high/$low/
$volume/$amount/$num_trades) start_index 不一致 — 因 RiceQuant 同步时
valuation/turnover 数据起点不同步于 price 数据起点。当 `Corr(safe_field,
broken_field, N)` 在多股票 universe 评估时, 内部 rolling 操作 shape 不
匹配 (e.g. 2620 vs 2674) → `np.isclose` broadcast crash, 整批 Phase 2
compute 终止。

**Corr-safe 字段集**: `$close, $open, $high, $low, $volume, $amount,
$num_trades`
**Corr-unsafe 字段集**: 全部 PIT valuation ($pe/$pb/$ps/$pcf), 全部 TTM
ratio ($peg/$pcf_total/$dividend_yield), `$turnover_rate`
