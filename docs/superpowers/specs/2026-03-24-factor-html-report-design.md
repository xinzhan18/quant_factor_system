# Factor HTML Report Generator — Design Spec

## Overview

Generate a self-contained, publication-quality HTML report for each admitted factor in the quant factor system. Reports combine LLM-generated narrative analysis with programmatically computed charts and metrics, rendered via a Jinja2 template into a single HTML file.

## Architecture

```
/factor-report <factor_id>          ← Claude Code Skill
         │
         ▼
   report_builder.py                ← Python: compute all metrics & charts
   ├─ Load factor metadata (YAML)
   ├─ Load factor_values + price_data (DB)
   ├─ Compute IC analysis (reuse ic_analyzer)
   ├─ Compute quintile analysis (reuse group_returns)
   ├─ Compute factor distribution stats
   ├─ Compute IC decay across holding periods
   ├─ Compute factor autocorrelation
   ├─ Compute annual/monthly IC breakdown
   ├─ Compute composite scores
   ├─ Export Plotly charts → HTML div strings
   └─ Output: report_data.json
         │
         ▼
   Claude Code (Skill)              ← LLM: write all narrative content
   ├─ Read report_data.json
   ├─ Write construction logic narrative
   ├─ Write economic interpretation narrative
   ├─ Write per-section data interpretations
   ├─ Write critical review (harsh critique)
   ├─ Write improvement suggestions
   └─ Output: narrative.json
         │
         ▼
   report_renderer.py               ← Python: assemble final HTML
   ├─ Read report_data.json + narrative.json
   ├─ Render Jinja2 template
   ├─ Embed Plotly JS inline (self-contained)
   ├─ Include MathJax via CDN for LaTeX
   └─ Output: factor_XXX_report.html (~2-5MB)
         │
         ▼
   Update DB: mining_factors.report_path
```

### Key Design Decisions

- **Three-stage pipeline**: Python computes data → Claude writes narrative → Python renders HTML. Clear separation of concerns.
- **Near-self-contained HTML**: Single file. Charts use `plotly-basic.min.js` via CDN (~1MB, supports all chart types used). MathJax also via CDN. Offline degradation: charts and formulas won't render but all text/tables remain readable. Realistic file size: ~500KB-1MB (no JS embedded).
- **Skill-based LLM integration**: No API keys or SDK needed. Claude Code itself writes the narrative content during skill execution.
- **Jinja2 template**: Ensures consistent report formatting across all factors. Template lives in `mining/report/templates/`.
- **LLM-generated metadata**: Chinese factor name (`name_cn`) and LaTeX formula (`expression_latex`) are generated by Claude Code in the narrative stage, not stored in YAML. This avoids changing the admission pipeline.

## Report Structure (8 Sections)

### Header
- Factor name: English from YAML (`name`), Chinese generated by LLM (`name_cn` in narrative.json)
- Factor ID, category, batch, admission date
- LaTeX formula: generated by LLM (`expression_latex` in narrative.json), rendered via MathJax
- KPI strip: IC Mean IS, IC Mean OOS, IC IR, Win Rate, Monotonicity, LS Return (annualized), Composite Grade

### Section 1: 构建逻辑 Construction Logic
**Source**: LLM narrative (informed by factor metadata + metrics)

- **1.1 公式分解 Formula Decomposition**: Step-by-step breakdown of the Qlib expression into mathematical operations. Show intermediate computations.
- **1.2 参数选择依据 Parameter Rationale**: Why this specific window/parameter was chosen. Reference batch history if relevant (e.g., batch_002 showed 10d and 60d windows are corr>0.8 with 20d).
- **1.3 预处理流程 Preprocessing Applied**: Visual pipeline diagram showing: Raw Factor → Filter Suspended → Winsorize (MAD 5σ) → Z-Score → Clean Factor. Note what was NOT applied (e.g., neutralization).

### Section 2: 经济含义 Economic Interpretation
**Source**: LLM narrative (deep analysis)

- **2.1 理论基础 Theoretical Foundations**: Core academic theory behind the factor. Not a textbook summary — explain why the anomaly persists and what market frictions sustain it.
- **2.2 多维度归因 Multi-Angle Attribution**: 3-4 distinct explanatory angles presented as cards (e.g., lottery preference, leverage constraints, attention effect, mean reversion). Each card includes the mechanism, key academic reference, and A-share relevance.
- **2.3 A股市场特殊性 China A-Share Context**: Institutional features that amplify or attenuate the factor (T+1, price limits, short-selling constraints, retail investor dominance).

### Section 3: 因子值分布特征 Factor Distribution
**Source**: Python computed + LLM interpretation

- **Statistics table**: Mean, Std, Skewness, Kurtosis, Coverage Rate, NaN Ratio — IS vs OOS with Delta column.
- **Charts**: IS vs OOS factor distribution overlay; Coverage rate time series.
- **LLM interpretation box**: Analyze distribution shape, stability across periods, extreme value characteristics.

### Section 4: IC 分析 Information Coefficient
**Source**: Python computed (reuse `ic_analyzer`) + LLM interpretation

- **4.1 汇总统计 Summary Statistics**: Table with IC Mean, IC Std, IC IR, Win Rate, |IC|>0.02 Rate, N Days — for IS and OOS periods.
- **4.2 IC 时间序列 & 分布**: Full-width IC time series (daily bars + 20d rolling mean + train/test split line); Two half-width charts: IC distribution histogram (IS vs OOS overlay), Rolling IC comparison (20d/60d/120d).
- **4.3 IC 累计曲线 Cumulative IC**: Cumulative sum of daily IC — shows trend consistency.
- **4.4 年度拆分 Annual Breakdown**: Table with IC Mean, IC IR, Win Rate per year + market regime label (Bull/Bear/Sideways). LLM interpretation of year-over-year trends.
- **4.5 月度 IC 热力图 Monthly IC Heatmap**: Plotly heatmap (Year × Month), diverging colorscale. LLM interpretation of seasonal patterns.

### Section 5: 分层分析 Quintile Analysis
**Source**: Python computed (reuse `group_returns`) + LLM interpretation

- **Charts**: Quintile annualized returns bar; Cumulative returns by quintile; Long-short (Q1-Q5) equity curve.
- **5.1 分组详细统计 Detailed Statistics**: Table with Ann. Return, Ann. Vol, Sharpe, Max Drawdown, Calmar, Win Days% per quintile + LS row.
- **5.2 样本内外对比 IS vs OOS Comparison**: Grouped bar chart (IS vs OOS quintile returns); IS vs OOS cumulative LS curves.
- **LLM interpretation**: Monotonicity analysis, practical investability (can you actually short Q5 in A-shares?), IS/OOS consistency.

### Section 6: 因子衰减 & 持续性 Decay & Persistence
**Source**: Python computed + LLM interpretation

- **Charts**: IC decay bar (1d/5d/10d/20d/60d holding periods); Factor autocorrelation plot (lag 1-20d).
- **Decay table**: Holding Period, IC, IC/1d_IC ratio, interpretation label.
- **LLM interpretation**: Half-life estimation, turnover implications, recommended holding period.

### Section 7: 综合评分 Composite Scorecard
**Source**: Python computed scores + LLM interpretation

- **Radar chart**: 6 dimensions — Predictive Power (|IC|), Monotonicity, Stability (IS/OOS consistency), Decay Resistance, Capacity (Coverage × Liquidity proxy), Uniqueness (vs library factors).
- **Score table**: Dimension, Score (0-100), Grade (A/B/C/D).
- **Composite score**: Weighted average with letter grade.
- **LLM interpretation**: Holistic assessment — what role does this factor play? Alpha source or risk control tool?

**Scoring methodology** (0-100 scale → letter grade):

Grade scale: A: 90-100, A-: 80-89, B+: 75-79, B: 65-74, B-: 60-64, C+: 55-59, C: 45-54, C-: 35-44, D: 0-34.

Dimension scoring (raw metric → 0-100 score via linear interpolation within grade bands):
- Predictive Power: Based on |IC mean|. 0→0.03=D(0-34), 0.03→0.05=C(35-54), 0.05→0.08=B(55-79), 0.08+→A(80-100).
- Monotonicity: Based on |monotonicity|. 0→0.4=D, 0.4→0.6=C, 0.6→0.8=B, 0.8+→A.
- Stability: Based on |IC_IS - IC_OOS| / |IC_IS|. >50%=D, 25-50%=C, 10-25%=B, <10%=A.
- Decay Resistance: Based on IC_20d / IC_1d ratio. <0.3=D, 0.3-0.5=C, 0.5-0.7=B, 0.7+=A.
- Capacity: Based on coverage rate. <70%=D, 70-85%=C, 85-95%=B, 95%+=A.
- Uniqueness: Based on max correlation with library factors. >0.7=D, 0.5-0.7=C, 0.3-0.5=B, <0.3=A.
- Composite: Equal-weighted average of 6 dimension scores → same grade scale.

### Section 8: 毒舌点评 Critical Review
**Source**: LLM narrative (deep, data-backed critique)

- **Opening**: One-sentence devastating summary.
- **Body**: 3-4 paragraphs of substantive criticism. Must reference specific numbers from the report. Must address: signal strength in practice, crowding/alpha decay, structural weaknesses, comparison with industry standards.
- **Key Weaknesses**: 4 cards with title + one-sentence explanation. Each card has a red left border.
- **Improvement Directions**: Bulleted list with actionable suggestions for improving the factor.

### Footer
- Generation timestamp
- System version identifier
- Credits: "Narrative by Claude Code · Charts by Plotly"

## Language Convention

- **Chinese**: All narrative text (construction logic, economic interpretation, LLM interpretation boxes, critical review)
- **English**: Metric names (IC Mean, Sharpe, Monotonicity), table headers, chart axis labels, section number prefixes, KPI strip labels
- **Mixed**: Section titles use both (e.g., "构建逻辑 Construction Logic")

## Skill Design: `/factor-report`

The skill orchestrates the three-stage pipeline:

1. **Read factor metadata**: Load `mining/library/factors/factor_XXX.yaml` to get expression, category, batch, metrics.
2. **Run report_builder.py**: Execute via Bash: `python -m mining.report.builder --factor-id <id> --output-dir /tmp/factor_report_<id>`. Script computes all metrics, generates all Plotly charts, outputs `report_data.json` to the output dir.
3. **Read report_data.json**: Claude Code reads `/tmp/factor_report_<id>/report_data.json` using the Read tool.
4. **Write narrative**: Claude Code generates all narrative content based on the metrics. Uses the Write tool to create `/tmp/factor_report_<id>/narrative.json`, following the exact schema defined in this spec. The skill prompt provides the JSON schema as a template.
5. **Run report_renderer.py**: Execute via Bash: `python -m mining.report.renderer --input-dir /tmp/factor_report_<id> --output-dir mining/reports/`. Script reads both JSON files, renders Jinja2 template, outputs `factor_<id>_report.html`.
6. **Update DB**: Renderer updates `mining_factors.report_path` with the output path.
7. **Report result**: Tell user the output path. Optionally open in browser via `open <path>` on macOS.

### Skill Prompt Guidelines for LLM Narrative

The skill prompt must instruct Claude Code to:
- Write as a **senior quantitative analyst** with deep industry knowledge
- Reference **specific numbers** from report_data.json in every paragraph
- Provide **3-4 distinct theoretical angles** for economic interpretation
- Include **A-share market specific** context (T+1, price limits, short-selling constraints)
- Write the critical review in a **sharp, witty, data-backed** tone — not generic criticism
- Each LLM interpretation box should draw a **non-obvious conclusion** from the data
- Use **Chinese** for all narrative, with English technical terms inline

## Jinja2 Template: Visual Design

- **Style**: Academic paper / research note aesthetic
- **Background**: White (#fafafa)
- **Font**: Georgia / Noto Serif SC (serif) for body; Courier New for formulas/code
- **Color scheme**: Section borders use distinct colors (blue/purple/teal/green/orange/blue/gold/red)
- **KPI strip**: Horizontal bar below header with key metrics
- **Section headers**: Left-border colored bar + section number + bilingual title
- **Data tables**: Clean lines, alternating row backgrounds, colored values (green positive, red negative)
- **Chart placeholders**: Plotly div containers with rounded borders
- **LLM interpretation boxes**: Light gray background (#f9fafb), bold "LLM 解读:" prefix
- **Critical review section**: Pink background (#fff8f8), red accents
- **Key Weaknesses**: 2×2 grid of cards with red left borders
- **Improvement Directions**: Green box with bulleted list
- **Footer**: Light gray, centered, generation metadata

### Market Regime Classification

Regime is determined by CSI 300 index annual return (computed from price_daily or a hardcoded lookup):
- **Bull**: CSI 300 annual return > +15%
- **Bear**: CSI 300 annual return < -15%
- **Sideways**: Otherwise

Lookup table for IS period (avoids needing CSI 300 data in DB):
```
2020: bull (+27.2%), 2021: sideways (-5.2%), 2022: bear (-21.6%), 2023: bear (-11.4%), 2024: sideways (+14.7%)
```
For OOS years, compute from available market data or update lookup.

## Error Handling

### Minimum Data Requirements
- Factor must exist in library YAML with at least `id`, `name`, `expression`
- Factor values must exist in DB (`mining_factor_values`) with ≥100 rows
- Price data must be available for the corresponding symbols and dates

### Partial Report Behavior
- If OOS data is insufficient (<30 days), OOS columns show "N/A" and LLM is informed to note limited OOS evidence
- If any chart computation fails (e.g., quintile returns with too few stocks), the chart placeholder shows "Chart unavailable: {reason}" and the section still renders with available tables/text
- If `report_builder.py` fails entirely, the skill reports the error and does not proceed to narrative generation

### Narrative Generation
- The skill instructs Claude Code to write narrative as a valid JSON file matching the `narrative.json` schema
- The skill provides the exact JSON schema as a template for Claude Code to fill
- `report_renderer.py` validates narrative.json keys before rendering; missing keys result in "Narrative unavailable" placeholder text

### Chart Serialization
- `builder.py` uses `plotly.io.to_html(fig, full_html=False, include_plotlyjs=False)` to get chart div strings
- `json.dumps(..., ensure_ascii=False)` for Chinese text in JSON
- Charts are HTML div strings in `report_data.json`; the Jinja2 template injects them via `{{ chart_html | safe }}`

## KPI Strip: ls_return

The `ls_return` stored in factor YAML is daily. The KPI strip displays **annualized** LS return (daily × 252). `builder.py` performs this conversion. The quintile stats table also shows annualized values.
