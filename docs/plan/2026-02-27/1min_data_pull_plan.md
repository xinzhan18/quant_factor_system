# 1分钟数据拉取计划

## 📊 数据量估算

| 指标 | 数值 |
|------|------|
| 时间范围 | 2015-01-01 ~ 2026-02-27 |
| 交易日数 | ~2,750 天 |
| 全市场股票 | 5,190 只 |
| 每日数据量 | ~64 MB / ~111万条 |
| **总数据量** | **~176 GB** |

## 🎯 拉取策略

### 方案A: 每日增量 + 历史补录 (推荐)

```
1. 先拉当天的增量数据 (今天就能用)
2. 然后后台慢慢补历史
3. 每天坚持，6个月完成
```

### 方案B: 一次性拉完

```
集中1-2周时间猛拉
- 风险: 可能触发米筐限额封号
- 优点: 快速完成
```

---

## 📅 详细计划 (方案A)

### 阶段1: 当天数据 (立即执行)
```bash
# 拉取今天的数据 (增量)
python scripts/pull_1min_data.py --date today
# 预计: 5分钟, 64MB
```

### 阶段2: 历史补录 (后台运行)

**策略**: 每天拉满1GB配额

| 天数 | 数据量 | 说明 |
|------|--------|------|
| 1-16天 | 16 GB | 拉满16天的全市场数据 |
| 17-32天 | 16 GB | 继续... |
| ... | ... | ... |
| 170-176天 | ~8 GB | 完成全部历史 |

**总耗时**: ~180天 (6个月)

### 每日运行时间

建议避开高峰时段:
- **推荐**: 凌晨 2:00 - 6:00 (低峰期，API响应快)
- **可选**: 下午 14:00 - 16:00

---

## ⚙️ 优化参数

当前脚本配置:
```python
BATCH_SIZE = 100        # 每批100只
DAILY_QUOTA_LIMIT = 5,000,000  # 500万条/天
```

**实际可拉**:
- 1GB ≈ 1600万条 (按64MB/天估算)
- 建议调高到: `10,000,000` (1000万条/天)

## 🚀 执行命令

### 1. 测试拉取今天数据
```bash
python scripts/pull_1min_data.py --date today
```

### 2. 批量补历史 (指定日期范围)
```bash
# 拉取2025年全年
python scripts/pull_1min_data.py --start-date 20250101 --end-date 20251231

# 拉取2024年全年
python scripts/pull_1min_data.py --start-date 20240101 --end-date 20241231

# 拉取2015-2023年
python scripts/pull_1min_data.py --start-date 20150101 --end-date 20231231
```

### 3. 后台持续运行 (Cron)
```bash
# 每天凌晨2点拉当天数据
0 2 * * * cd /path/to/quant_factor_system && python scripts/pull_1min_data.py --date today
```

## ⚠️ 风险控制

| 风险 | 应对措施 |
|------|----------|
| 米筐限额 | 每日监控，接近1GB自动停止 |
| 网络断开 | 断点续传，记录进度 |
| 数据库写入失败 | 事务保证，失败重试 |
| API封号 | 请求间隔，降低并发 |
